# v1.5.0 主要优化：
# 1) 评论热路径零嵌套分配轻量解析：原先每条评论都用标准 proto.Unmarshal 反序列化
#    CommonActionSignalComment，其间会 reflect.New 出 ZtLiveUserInfo / ZtLiveUserIdentity /
#    ImageCdnNode 等嵌套消息（pprof 显示该部分占 HandleActionSignal 分配量近四成）。
#    新增 fastdecode.go 仅提取业务所需字段（content / sendTimeMs / userId / nickname /
#    avatar[0].url / badge / managerType），不再构造任何嵌套 protobuf 消息。
#    parseCommentFast 遇到任何非预期编码一律返回 ok=false，由 handleActionSignal 回退到
#    标准 proto.Unmarshal，因此行为正确性不被破坏（见 fastdecode_test.go 的对照测试，
#    快速路径与标准路径逐项比对完全一致）。
# 2) 事件分发快照去冗余：handleActionSignal 的逐条分发循环原先每条弹幕都 atomic.Load 一次
#    handler 快照并重复 map 查找；改为在批次开始时只加载一次快照并复用 dispatchEvent，
#    减少热路径上的原子读与查找开销。
# 3) newUserInfo 惰性取解析器：仅当存在徽章时才从 medalParserPool 借用/归还解析器，
#    无徽章的弹幕（绝大多数）省去一次 sync.Pool 往返与 defer 开销。
# 4) state/notify 对象池归还修复：handleStateSignal / handleNotifySignal 原先在 per-item
#    循环内用 defer putProto，导致对象在整个信号处理结束前无法在 item 间复用、且带来循环内
#    defer 开销；改为每条 item 用完即还，多 item 间可复用同一池对象，并消除 defer 开销。
# 5) 健壮性：修复 newUserInfo(nil) 的潜在空指针 panic（部分不含 userInfo 字段的构造消息会触发）。
#
# 关于池化内层消息安全性的验证：google.golang.org/protobuf 在 Unmarshal 时会对 string 字段
# 做拷贝（不零拷贝引用输入缓冲），快速路径同样通过 string(b[a:b]) 显式拷贝，已派发的弹幕
# DanmuMessage 持有独立拷贝，池化与复用均安全（见 alias_test.go: TestProtoStringAliasing）。
